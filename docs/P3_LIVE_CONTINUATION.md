# P3 — 外部 OpenCode 会话的有界接续（原型设计 v2）

状态：设计（未实现，生产入口关闭）。仅限隔离样本；用户真实会话必须按**具体对象逐项审批**。
本版按评审修正：备份一致性、无写者证明、进程影响集合、新来源授权契约、双写隔离。

## 1. 可核验的原来源身份（只读）
采集并冻结 `origin-identity.json`：
- `sessionId` / `nativeSessionId` / `cwd`（截断即 unknown）
- 驱动进程 `pid` + startTicks + 可执行文件 inode/hash
- 会话存储：**SQLite 主库 + WAL/SHM 作为一组**，路径、inode、size、mtime、`pragma quick_check`
- 运行时端点 `127.0.0.1:<port>`、凭据指纹（不落明文）、manifest 哈希
- 任一不可读 → `UNKNOWN`，终止（只读）。

## 2. 一致快照（不是硬链接）
- 硬链接/单文件复制 **不是** 快照：写入会改变同一 inode；SQLite+WAL 复制单文件不一致。
- 使用受支持的在线备份（SQLite backup API / `VACUUM INTO` 到新文件）或**停写后**的一组
  一致拷贝（主库+WAL 同时点、校验 `quick_check` 与行数）。
- 生成 `snapshot.json`（sha256、行数、schema 版本）并在临时库**恢复验证**后才允许继续。
- 回滚只写回"新副本"，**禁止**向共享源库盲目覆盖；恢复失败即 `quarantined`。

## 3. 无写者证明与释放（单对象、非泛化）
- 仅当以下全部成立才认为释放完成：原驱动**可验证地**放弃独占租约（释放记录/租约过期且
  不可续）、阻止自动重启（重启策略/端口占用核验）、进程与存储域无其他写者。
- PID 消失 + 端口关闭 + 文件短时不变 **不构成** 证明；无法证明 → `quarantined`，
  不授予新绑定。
- 进程影响集合：先枚举该进程服务的**全部会话**。一个进程服务多个会话时，
  单会话释放不成立；只允许"专属进程"方案。生产不自动把 SIGTERM 升级为 SIGKILL。
- 审批必须点名：pid+startTicks、受影响的会话集合、存储快照、回滚方式。

## 4. 新来源授权契约（p3_live_continuation）
- 与旧 `external_observer`/`legacy_unknown` 只读行**并存**：旧行保持只读，不原地改 origin。
- 新绑定必须同时通过统一检查：Actor 权限 + 本次审批 id + 实例代数 + 原生身份 +
  **旧驱动拒绝写**（lease/refusal 证据）；缺一不可，写 origin 本身不产生控制权。
- 不可变交接台账 `p3_handoff`（append-only）：identity 指纹、快照指纹、审批对象与范围、
  释放证据、新绑定 id、结果。禁止更新/删除既有行。
- 上下文保留：一次性暗号必须出现在**模型请求**中且模型据此作答；新轮达因果终态。

## 5. 失败与双写
- 新侧尚未产生工作：按审批回滚（恢复原驱动或保持只读）。
- 新侧已产生工作：**先证明新侧释放**；证明不了 → `quarantined`，绝不双写、不盲目恢复。
- 所有失败都记录到交接台账并保留快照。

## 6. 边界
首版仅隔离样本；生产入口关闭；不改既有授权守卫与 P2 claim/token 语义。
