# P3 — 外部 OpenCode 会话的有界接续（原型设计）

状态：设计（未实现，生产入口关闭）。只允许在隔离样本上演练；用户真实会话必须按**具体对象逐项审批**后才可释放，绝不自动停止。

## 1. 可核验的原来源身份（只读）
在动任何东西前采集并冻结一份 `origin-identity.json`：
- `sessionId`、`nativeSessionId`、`cwd`（真实路径，截断则判 unknown）
- 驱动进程：`pid` + `/proc/<pid>/stat` startTicks + 可执行文件 inode/hash
- 会话文件/目录：路径、inode、mtime、size、内容 sha256
- 运行时端点：`127.0.0.1:<port>`、Basic 凭据指纹（不落明文）、实例 manifest 哈希
- 判定：上述任一不可读 → `UNKNOWN`，流程终止（只读）。

## 2. 释放机制（仅一个明确对象）
- 目标对象唯一：`pid + startTicks + nativeSessionId + 会话文件 hash` 全部匹配才允许操作；任一漂移 → 中止。
- 顺序：先取得显式审批（列出以上对象与将执行的动作）→ 释放前再校验一次身份 →
  优雅 `SIGTERM` 原驱动 → 等待退出（超时则 `SIGKILL` 并记录）。
- 写权证明：退出后确认 pid 不存在、端口关闭、会话文件 mtime/size 不再变化；
  **不以"进程不在"单独作为失去写权的证据**，须同时满足文件与端口检查。
- 回滚：文件在释放前做硬链接/拷贝快照（不修改原文件）；失败时恢复原驱动启动命令或
  保持只读观察；任何一步失败都不得进入新绑定。

## 3. 新绑定与上下文保留
- 以同一 `nativeSessionId` 建立新的受信绑定（新 instanceId/generation），绑定记录来源为
  `p3_live_continuation`，并保存 origin-identity 指纹与审批 id。
- 上下文保留验证：注入一次性暗号（fork 暗号法），从**模型请求**确认新侧历史包含该暗号，
  并要求模型依据暗号作答；DOM 文本不作为证据。
- 真实新轮：新侧发送一轮 → 因果终态（assistant.parentID = 本轮用户 messageID，
  step-finish=stop）→ 原侧无写权（文件/端口不变）。

## 4. 成功判据 / 反例
成功：身份一致、释放有审批、写权证据完整、暗号进入模型请求、新轮到达因果终态。
反例必须失败并回滚：身份漂移、审批缺失、文件在释放后仍被写、端口仍开放、
暗号未进入模型请求、新轮无因果终态。

## 5. 边界
- 首版仅隔离样本；生产入口保持关闭。
- 不删除、不改写原始会话文件；不做"接管"以外的副作用。
- 与 P2 重连/claim 语义隔离：本流程只创建新绑定，不触碰既有 claim/token 规则。
