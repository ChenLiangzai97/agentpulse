# /fork 隔离验证报告（1.18.35）——结论：原生语义不可用，本轮 NO-GO

验证环境：CLI 1.18.35 隔离实例（--pure + 独立 XDG + OPENCODE_CONFIG），先以 P0 mock 模型
验证机制，再以真实短会话（≤3 轮、廉价 flash 模型）验证上下文继承。全部请求/响应留有
fixture 生成方法，可一键复跑。

## 实测事实

1. `POST /session/{id}/fork {messageID}` 返回新会话对象（title 带 "(fork #N)" 后缀），
   **message 列表为空**、`parentID` 未设置（DB parent_id 为空）。
2. 父会话不受影响（消息数不变）；分支可独立发消息。
3. **分支不继承分叉点之前的上下文**（决定性实验）：父会话注入暗号 → 在含暗号消息处分叉 →
   向分支询问暗号，真实模型回答"我不知道"（input tokens 仅系统提示规模）；PATCH parentID
   重新挂父后再次询问，仍不知道。
4. 服务端没有任何消息历史复制/迁移 API：OpenAPI 162 路径中仅有 revert/unrevert（同会话内
   撤销）与 share；无 copy/clone/export-import。
5. 即 fork 端点在 1.18.35 只产生一个"空的新会话 + 标题后缀"，不带历史；TUI 的 /fork 语义
   应由客户端重建（不在服务端 API 能力内）。

## 对两个候选方案的判定

- 同实例多分支受保护绑定：绑定/队列/审批/回收机制上可行，但**没有历史继承就不是分叉**，
  只是"同实例新会话"；按规格不得冒充 fork。
- 独立实例真实历史迁移：无迁移 API，唯一途径是把历史拼进 prompt——被规格明确禁止。

## 结论与选项（待用户决定）

/fork 本轮 NO-GO：无法在不违反"禁止历史拼 prompt / 禁止 observer 升级 / 禁止 native ID
冒充"约束下实现真分叉。可选：
A. 等上游版本提供服务端真 fork（升级适配后重验证）；
B. 降级提供"从某消息处新建空分支会话"（明确标注不含历史，仅记录 fork 来源与 messageID 于
   受保护元数据），命名不得使用"分叉继承"字样。
