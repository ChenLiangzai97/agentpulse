# /fork 隔离验证报告（1.18.35）——修订版：原生历史分叉语义成立

> 本版推翻前一版 NO-GO 结论：当时的实验在"包含暗号的那条消息"处分叉，而原生语义
> 是**排除指定消息本身及其后**，因此分支确实不知道暗号——方法错误，结论错误。
> codex 的三处质疑（边界语义、消息格式、方法学）全部成立并已按其方法论重做。

验证方式：`fork_probe.py`（隔离实例 + 真实 glm-5.3-flash，可一键复跑）；证据：
`fork-evidence.json`（请求/响应/消息清单）与 `fork-evidence-messages.json`（含正文，
脱敏后仅测试词汇）。父会话两轮完整对话（苹果/香蕉），三种分叉各一次。

## 实测语义（全部有真实模型作答佐证）

| 分叉方式 | 分支历史（消息为**内容拷贝、全新 messageID**） | 询问暗号的回答 |
| --- | --- | --- |
| 省略 messageID | 完整两轮（4 条拷贝） | "苹果、香蕉" |
| 指向最后一条 assistant | 3 条拷贝（u1,a1,u2；**排除指定的 a2**） | "苹果 香蕉" |
| 指向中间 user（u1） | 空（**排除 u1 及其后全部**） | "（你还没有说过任何暗号）" |

结论：
1. `POST /session/{id}/fork` 是**服务端真历史分叉**：拷贝指定消息之前的全部消息（新
   messageID、正文与角色保留），分支可独立继续对话；父会话不变（消息数、内容均不变）。
2. 分叉点语义 = "回退到该消息之前重开"（排除指定消息本身）；省略 messageID = 全量拷贝。
3. 分支 parentID 为空、同 directory；分支新消息的计费只发生于其后的新轮次（拷贝行本身
   不调用模型）。拷贝行是否携带历史 cost 字段见 evidence 原始 JSON（stats 侧按"历史拷贝
   不计费用"处理，见影响矩阵）。
4. messageID 使用原生 GET message 返回的真实 ID（msg_* 格式），按 time 排序核对无误。

## 同实例多分支受保护绑定：影响矩阵（待评审后实施）

- **绑定**：分支=新 AgentPulse 会话 + 独立受保护绑定（origin=agentpulse_launch，同
  instanceId，nativeSessionId=分支 ID）；`bindCreatedOpenCodeSession` 现有校验
  （cwd/agentType/launch 链）不满足分支场景，需要新增"同实例分支绑定"入口，复用
  generation 栅栏；不写 observer 子会话、不升级外部来源。
- **队列**：实例内每会话原生可并行，但 v1 保持与根一致的实例级 idle 等待（排队栅栏跨
  根/分支共享，避免同实例并发写工作区文件）。
- **审批/提问**：interactions 按分支 nativeSessionId 归属到对应 AgentPulse 会话；快照需
  按绑定 ID 分发而非并入根。
- **中止/停止**：分支"中断"= 原生 `/session/{分支}/abort`（仅该分支）；分支"停止"=
  abort + 该绑定 closed（实例存活）；根"停止实例"= 整实例停（含全部分支，需 UI 明示）。
- **回收**：实例 idle 回收已计入 descendants 活动；分支绑定随实例停止失效。
- **重启**：恢复走既有 manifest + /session 扫描（分支同 directory 可被重新发现）；绑定行
  持久，代际校验照旧。
- **统计**：分支历史拷贝产生的消息事件标记 replayed（不计今日费用/工作日志）；仅分支
  新轮次计费。

## 仍未证实

- 并发写同一工作区文件的风险仅靠"实例级排队"缓解，未做多分支并行实测（本轮不开放）。
- 拷贝行的 cost/tokens 字段保留情况：见 evidence 原始 JSON；stats 侧不采信拷贝行费用。
